The bot runs on its own timeline. Every method that waits for it starts with `waitFor`, and none of them sleeps.

| To…                              | Use                                                |
| -------------------------------- | -------------------------------------------------- |
| wait for a message the bot sends | `await discord.waitForMessage(channel, /text/)`    |
| wait for a DM the bot sends      | `await discord.waitForDM(member, /text/)`          |
| check the bot sent nothing more  | `await discord.waitForIdle()`, then assert         |
| read what's there now            | `discord.messages(channel)`, `discord.dms(member)` |

## `waitForMessage` and `waitForDM`

Waits up to 2 seconds for a message the bot created or edited **since the latest action** whose text contains the string or matches the RegExp. The text is the content plus each embed's title, description, fields and footer. `waitForMessage` looks in a channel or thread, `waitForDM` in a member's DMs with the bot. On timeout it fails and shows the last three messages there.

Only the bot's messages count, so a member's own `!ping` never satisfies `waitForMessage(channel, /ping/)`.

## `waitForIdle`

Resolves once the bot has no request open to Discord and nothing new has reached it for 100ms. Use it before asserting the bot sent exactly one reply, or none.

A bot that works for longer than 100ms before its first request looks done. Wait on `waitForMessage` for what it should send instead.

## Before a click or a pick

`click` and `select` first wait until the bot has been quiet for 100ms: no request to Discord open, nothing new sent to it. A member reads a message before using it, and a bot often fetches its reply and starts listening for the buttons just after sending it.

That wait adds up: 40 clicks spend 4 seconds in it. Change it for the whole test with `createDiscord({ quietTimeMs: 20 })`; 0 still waits for every open request.

Lower it only when the bot does nothing between sending a message and listening for its buttons. The kit can't see the bot's database queries or timers, so that work has to fit in the wait. If it doesn't, the click lands before the bot listens, and the test fails with "The application did not respond" although the bot works on Discord.

## Threads and sound

`waitForThread(channel, name)` waits for a thread the bot starts in `channel`, by name. `waitForThreadFrom(message)` waits for the thread the bot starts from `message`, whatever it names it. `waitForTextChannel(server, name)` waits for a text channel in the server, by name, such as a ticket channel the bot opens. `waitForSound(channel)` waits for the bot to play sound in a voice or stage channel. Each gives up after 2 seconds.

## Anything else

For state outside Discord, such as the bot's database, use `await vi.waitFor(() => expect(…))`.
